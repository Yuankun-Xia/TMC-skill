# TMC Paper to Presentation

Turn the paper's argument into an understandable talk. Read [slide story and evidence](references/slide-story.md) and [TMC context](references/tmc-context.md). This skill supplies scientific content guidance; use the presentation authoring tools actually available for PPTX, editable slides, notes, rendering and export. Do not promise a specific tool or template that is not present.

## Establish the talk

Recover source/version, audience, language, purpose and time limit from context. Use a reasonable provisional talk length when the request leaves it open and state the assumption. If the user asks for a PPTX, produce an actual PPTX when tools permit; an outline is an intermediate step. Report a missing export capability honestly if it prevents the requested output.

## Build the narrative

1. Read the relevant complete paper, including methods, evaluation, limitations and figures. Label abstract-only or partial access.
2. Establish the mobile setting, bottleneck, design insight, operation, decisive evidence and boundaries.
3. Use each slide to answer one audience question. Do not map every paper paragraph or section to an equally weighted slide.
4. Explain system entities and the execution timeline before dense optimization or convergence equations. Keep only the math needed for the insight and guarantee; move detail to backup slides when appropriate.
5. Reuse/crop actual source figures where authorized and readable; retain captions/panel labels and add source anchors. Label redraws and any omitted panels. Do not generate experimental curves or invent missing values.
6. Separate author claims, reported evidence and the presenter's critique or extension idea. Match system claims to time/energy/memory/traffic/mobility/attack evidence as applicable.
7. Add speaker notes with explanation and transitions when useful or requested. Keep source page/figure/section references on slides or in notes.
8. Render and inspect the final deck for text overflow, tiny formulas, unreadable plots, cropped panels, contrast and missing assets. Verify the actual file and slide count before delivery.

## Deliver

Return the requested slide artifact plus concise notes on assumed audience/duration and any inaccessible source content. Add a talk script or source map when requested or materially useful. Do not create extra documents by default. An unrendered deck should not be reported as visually verified.
